# 민원 전화 설명의 기록과 서면 확인

전화 설명은 기존 민원의 경과로 기록한다. 전화 설명 수신, 서면 회신 수신, 기관의 처리 완료, 문제 해결은 각각 구분한다. 사실 질의에 대한 전화 설명은 질문별로 대조하고, 남은 항목을 기존 접수 건의 서면 답변에 반영하도록 요청한다.

## 기록할 항목

통화 시각과 시간대, 제공받은 기록의 종류, 화자와 부서, 관련 접수 건, 질문별 설명, 후속 답변의 약속 범위를 기록한다. 통화 기록에서 접수번호를 확인할 수 없으면 주제에 따른 연결임을 표시하고 포털에서 대조한다.

자동 전사는 원음과 구분한다. 발췌를 저장할 때는 전체 전사가 아니라는 점과 선택한 구간을 표시한다. 금액·날짜·화자명이 충돌하면 값을 합치거나 임의로 고치지 않는다. 원음 또는 공식 문서로 대조한다. 통화 기록과 분석은 Git에서 제외되는 `data/complaints/`에 보관한다.

| 전화 설명 | 남길 후속 질문 |
| --- | --- |
| 검토하지 않았다는 설명 | 어떤 검토와 대상·시점을 뜻하는가 |
| 관련 자료가 없다는 설명 | 검토 미실시인가, 현재 자료를 보유하지 않는다는 뜻인가 |
| 지금 계산하거나 검토할 수 있다는 설명 | 기존 결정 당시의 검토와 이후 새 검토를 구분할 수 있는가 |
| 개선을 검토 중이라는 설명 | 과제·담당·범위·단계와 공개 가능한 일정은 무엇인가 |
| 여러 기관 또는 규정에 따라 운영한다는 설명 | 구체적인 근거 조문과 기관별 조정 권한은 무엇인가 |
| 서면 답변이 어렵다는 설명 | 원래 질문별 전자문서 답변이 가능한가. 전화 통지로 종결한다면 적용 근거는 무엇인가 |

발언을 요약할 때는 부정 문장과 그에 대한 설명을 함께 기록한다. 특정 분석에 대한 답변을 기관 전체의 분석 부재로 확대하지 않는다. 짧은 동의 표현은 구체적인 사실 인정으로 확정하지 않는다. 답변 제공 의사는 답변 기한이나 완료 약속과 구분한다.

## 서면 확인 요청

기존 질문의 미답변 부분을 추린 뒤 포털에서 실제 제공하는 후속 제출 경로를 확인한다. 처리 중인 민원에 요청글을 추가할 수 있다고 가정하지 않는다.

서울시 응답소의 공개 안내를 2026년 10월 8일 확인한 결과는 다음과 같다.

| 단계 | 확인된 기능과 확인 범위 |
| --- | --- |
| 접수 전, 진행상황이 `신청` | 기존 민원 내용 수정 가능 |
| 접수 후, 이송 또는 처리 중 | 기존 민원 내용 수정 불가. 별도 요청글 추가 기능은 확인하지 못함 |
| 처리 완료 후 | 처리절차 안내의 사후관리 단계에 추가 문의가 있음. 로그인한 개별 민원의 실제 버튼과 이용 조건은 확인 전 |

근거: [응답소 민원 내용 수정 FAQ](https://eungdapso.seoul.go.kr/not/faq/faq_vie.do?faqSeq=311&searchType1=&sk=&sv=&cp=1), [응답소 민원 처리절차](https://eungdapso.seoul.go.kr/not/guide/process_guide.do). 내용 수정과 별도 요청글 추가는 다른 기능이다. 공개 안내만으로 처리 중인 민원의 요청글 추가 가능 여부를 확정하지 않는다.

실제 추가 경로가 확인되지 않으면 기존 민원을 유지하고 별도 보충민원을 작성한다. 원민원 번호, 새 통화 시각, 서면 확인이 필요한 항목을 적어 연결을 요청한다. 원문을 그대로 반복하기보다 통화 이후 확인할 내용을 명시한다. 새 접수번호를 받으면 별도 사건으로 기록하고 `parent_case_id`로 기존 사건에 연결한다. 기존 민원을 취하할 필요는 없다.

```text
전화로 설명해 주신 내용에 감사드립니다. 기존 질의 중 다음 사실 항목에 각각 전자문서로 답변해 주시기 바랍니다.

1. 해당 검토의 실시 여부, 대상과 실시 시점.
2. 검토자료의 문서명, 주요 가정과 결과. 검토 미실시와 현재 자료 미보유를 구분해 주십시오.
3. 현재 개선 검토의 담당·범위·단계와 공개 가능한 향후 안내 계획.
4. 기존 질문 중 남은 항목과 현재 민원 처리 상태.

전화 설명을 서면 답변에도 반영해 주시고, 제가 이해한 내용이 다르다면 해당 항목을 바로잡아 주십시오.
```

민원 처리에 관한 법률 제27조는 접수된 민원의 처리 완료 후 문서 통지를 원칙으로 두고 전자문서 통지도 허용한다. 기타민원, 신속 통지가 필요한 경우, 민원인의 요청 또는 동의가 있는 경우 등에는 예외가 있다. 전화가 왔다는 사실만으로 법 위반이나 적법한 종결을 확정하지 않는다. 실제 접수 절차, 민원 종류와 통지 상태를 확인한다. [법 제27조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025681371), [시행령 제29조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0029&lsiSeq=285815&urlMode=lsScJoRltInfoR).

## 장부와 자료 청구

기존 [이벤트 형식](event.example.json)의 `source.kind=shared_user_quote`로 사용자 제공 전사를 연결하고, `note`에 통화 시각·관련 사건 연결의 근거·전사 파일 위치를 남길 수 있다. 관련 질문에 `partial`을 기록하면 `response_evidence`에 전화 전사라는 점과 구간을 명시한다. `next_action`에는 서면 확인할 내용을 남긴다.

전사만으로 `evidence_status=confirmed`, 포털의 `status_raw`, `last_checked_on` 또는 서면 회신일을 갱신하지 않는다. 구두 설명은 공식 서면 회신과 별도 기록으로 보존한다. 기록 명령은 [민원 추적 장부](README.md#장부-사용)를 따른다.

자료 존재 여부가 남으면 기존 보고·회의·협의·계산자료를 식별해 정보공개청구를 검토한다. 기간과 주제를 좁히고 신규 분석 작성을 요구하지 않는다. 부존재 통지는 해당 기관·기간·청구 범위에서의 자료 미보유로 해석한다.

## 통화에서 후속 민원과 제안 도출

질문별 사실 확인, 기존 자료 확보, 향후 제도 개선을 별도 요청으로 설계한다. 기존 민원과 겹치는 질문은 전화 이후 새로 확인할 내용과 함께 보충 요청으로 묶는다. 서로 다른 기관이나 목적의 요청만 분리한다.

| 전화에서 나온 설명 유형 | 후속 요청의 목적 |
| --- | --- |
| 분석이 없거나 부족하다는 설명 | 당시 실시 여부와 현재 자료 보유 여부를 각각 확인. 공급·결정 전 검토 절차를 개선하는 제안으로 연결 |
| 여러 규정이 별도로 적용된다는 설명 | 기관별 조정 권한을 확인. 기준을 함께 적용한 결과를 검토하는 공동 절차 제안 |
| 개선책을 이미 시행했다는 설명 | 시행 전후 효과와 남은 부담을 확인. 같은 개선책의 도입 요청을 반복하지 않음 |
| 지금 새로 계산할 수 있다는 설명 | 기존 결정 당시 자료와 새 분석의 작성 시점을 구분 |
| 제도 개선을 검토 중이라는 설명 | 과제명·담당·단계·다음 안내 시점을 확인. 회신 수신과 실제 변경 시행을 별도 추적 |
| 문맥 또는 인용 문제로 서면 답변이 어렵다는 설명 | 사실 답변과 배경 설명을 함께 쓰는 표준 답변 형식 제안. 특정인의 의도를 전제하지 않음 |

각 후보에는 요청 제목, 제출 기관 후보, 기존 민원과의 차이, 요청할 결과물, 공개 근거, 남은 확인 조건을 적는다. 후보 작성은 접수 완료가 아니다. 개인 통화 기록과 실제 후보 문안은 비공개 자료에 보관한다.

서울시의 일반 질의·건의는 [응답소](https://eungdapso.seoul.go.kr/main.do), 공개 정책 제안은 [상상대로 서울](https://idea.seoul.go.kr/front/index.do)에서 경로를 확인한다. 2026년 10월 8일 상상대로 서울 안내는 30일 동안 50개 이상 공감을 받은 제안을 담당부서가 30일 검토 후 답변한다고 설명한다. 공개 제안을 등록했다는 사실만으로 부서 답변이 보장된다고 기록하지 않는다. 정보공개청구는 [정보공개법 제11조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1011235965)에 따른 기존 자료 요청으로 설계한다. 새 분석이나 신규 통계 수집은 일반민원·정책 제안으로 요청한다.
