# 민원 후속 절차 실행 계획

후속 작업은 기존 사건 확인, 사실 답변과 자료 확보, 정책 개선 제안, 답변 대조, 실제 변경 확인 순서로 진행한다. 같은 기관에 같은 결과를 요청하는 항목은 묶는다. 새로운 정책 제안은 과거 사실의 확인과 함께 준비할 수 있다.

## 단계와 결과물

| 단계 | 작업 | 다음 단계로 넘길 결과물 |
| --- | --- | --- |
| 1 기존 사건 확인 | 접수번호·본문·담당기관·현재 상태·처리예정일·연장 통지를 대조 | 원문과 출처 시각이 있는 사건 기록 |
| 2 첫 요청 준비 | 전화 이후 확인할 사실과 필요한 기존 자료를 분리 | 서면 확인 보충민원과 정보공개청구 제출 묶음 |
| 3 정책 제안 준비 | 사전 검토 절차, 시행 효과 평가, 대안 비교, 신청 안내를 하나의 개선 목적에 연결 | 담당기관·요청 항목·시범 범위·완료 기준을 적은 제안 |
| 4 답변 대조 | 각 질문과 공개 자료를 실시 여부·시점·가정·결과에 대조 | 답변표와 미답변 목록 |
| 5 조건별 후속 조치 | 자료 미보유·권한 제한·질문 누락·처리 지연을 구분 | 해당 기관과 남은 항목에 한정한 다음 요청 |
| 6 변경 확인 | 계획·지침·모집공고·운영 결과의 변경을 확인 | 실제 적용 문서와 개선 결과 |

## 제출 묶음

첫 묶음은 전화 설명의 서면 확인과 관련 기존 자료 공개청구다. 두 절차는 병행할 수 있다. 기존 접수 건은 유지한다. 처리 중인 민원에 추가 기능이 있다고 가정하지 않고, 관찰한 기능 또는 기존 번호를 인용하는 별도 보충민원을 사용한다. [전화 설명과 후속 경로](phone-followup.md)를 따른다.

새 보충민원을 제출하기 전에 이미 접수된 보충민원의 본문과 상태를 확인한다. 같은 질문이 처리 중이면 중복 제출을 보류하고 기존 서면 답변을 점검한다. 기존 문서 공개청구와 향후 정책 제안은 요청하는 결과가 다르므로 별도로 준비할 수 있다. 포털 목록이 비어 있으면 다른 관찰된 조회 경로를 확인한다. 한 목록에 없다는 이유로 기존 접수를 없던 것으로 처리하지 않는다.

정책 제안은 요청할 개선 절차를 중심으로 묶는다. 과거 분석 실시 여부가 아직 확인되지 않았다면 그 상태를 표시하고, 향후 검토 절차의 필요성과 개선안을 설명한다. 모든 자료가 도착해야만 제안을 준비할 수 있는 것은 아니다.

기관별 권한 확인과 답변 작성 절차 개선은 필요할 때 분리한다. 조정이 막히면 제한 조문·위임 범위·소관을 확인한 뒤 규정 개선을 요청한다. 질문이 누락되면 해당 질문과 실제 회신 문구를 대조한 표로 보충 요청을 설계한다.

## 점검 일정과 후속 조건

내부 목표일과 포털 처리예정일을 구분한다. 내부 목표일은 법정기한이 아니다. 실제 접수일, 민원 종류, 이송·연장 통지와 법령의 기간 계산 기준을 확인한 뒤 기한 관련 후속 절차를 정한다. 응답소는 민원 종류별 처리기간과 계산 기준을 별도로 안내한다. [응답소 처리절차](https://eungdapso.seoul.go.kr/not/guide/process_guide.do).

| 관찰 결과 | 후속 작업 |
| --- | --- |
| 분석 또는 검토자료를 받음 | 작성 시점이 결정 전인지 확인하고 가정과 결론을 대조 |
| 해당 범위의 분석 미실시를 서면으로 확인 | 향후 사전 검토 절차와 시행 계획을 요구하는 제안에 연결 |
| 현재 자료를 보유하지 않는다고 통지 | 기관·기간·항목을 보존하고 다른 보유기관 또는 미보유 사유 확인 |
| 법령 근거 또는 검토 중이라는 설명만 있음 | 원래 사실 질문의 누락과 과제명·담당·단계·다음 안내 시점만 좁혀 요청 |
| 처리예정일이 지났고 유효한 연장·최종 답변을 확인하지 못함 | 접수·이송·연장 경과를 먼저 확인하고 적합한 처리 경과 확인 절차 검토 |
| 정보공개 결정에 불복하거나 무결정에 관한 법정 요건이 충족됨 | 실제 청구·통지 날짜와 요건을 확인해 이의신청 등 적용 절차 검토 |
| 개선 검토나 수용 답변을 받음 | 약속한 다음 단계와 실제 지침·공고 반영을 구분해 추적 |

민원 처리 완료 후 문서 통지 원칙과 예외는 [민원 처리에 관한 법률 제27조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025681371)에 따른다. 자료 공개 결정과 자료 부존재·질의 등의 처리 조건은 [정보공개법 제11조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1011235965), 이의신청 요건은 [제18조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031228369)를 대조한다. 서로 다른 절차의 기한을 하나로 계산하지 않는다.

## 기록과 완료 기준

접수 완료, 질문별 답변 수신, 정책 개선 검토, 실제 시행은 각각 기록한다. 제출 건수가 늘었다는 사실을 개선 성과로 보지 않는다. 수용 답변만으로 문제를 해결한 것으로 기록하지 않는다.

개별 계획과 제출 본문은 Git에서 제외되는 `data/complaints/plans/`에 둔다. 접수 확인 전에는 실제 접수번호나 제출 완료 상태를 만들지 않는다. 접수 후에는 [추적 장부](README.md#장부-사용)에 새 사건과 근거를 연결한다.

새 제출을 시작할 때는 먼저 장부에 접수번호가 없는 준비 사건을 만든다. 제출 직전에 접수 결과 미확인 상태를 기록하고, 수리 화면을 확인한 뒤 실제 번호와 제출 상태를 기록한다. 준비 사건과 수리된 사건의 수를 구분한다.

연결된 Mac에서 실행할 때는 실제 실행 호스트와 비공개 자료 위치를 먼저 확인한다. 계정 준비와 원격 로그인 성공은 별도 상태다. [원격 실행 지침](remote-runbook.md)과 [computer use 실행 지침](computer-use.md)을 적용한다. 계획 문서의 날짜만으로 정기 조회나 알림이 실행되지는 않는다.
