# 불합리한 행정과 제도를 찾는 조사 방법

기준일: 2026년 10월 8일 KST

문제 발굴은 **반복 민원 분석, 규칙과 근거의 비교, 실제 절차의 부담 측정**을 함께 사용한다. 민원이나 보고서에서 문제 후보를 찾는다. 현재 규정과 실제 사례로 원인을 검증한다. 이후 담당기관에 요구할 변경과 확인할 결과를 정한다.

이 문서는 공식 자료에서 확인한 조사 방법과 이를 개인 민원 운영에 적용하는 실행안을 구분한다. 특정 제도가 부당하다는 결론이나 새로운 민원의 제출 사실을 기록한 문서는 아니다. 문제를 처리하는 전체 전략은 [민원 개선 전략](strategy.md)에 있다.

공개된 변경 계획을 시행 전에 검토하는 방법은 [입법·행정의 사전 탐지](early-warning.md)에 정리했다. 계획·예고·발의·예산·구매 자료에서 후보를 찾고, 조문과 사업 조건의 변경, 결정 단계와 의견 기한을 함께 추적한다.

## 조사에서 확인한 방법

OECD의 2024년 보고서는 공공서비스의 불필요한 부담을 찾아 측정하는 `sludge audit`를 설명한다. 여기서는 이를 **절차 부담 점검**이라고 부른다. 시간과 비용뿐 아니라 혼란, 노력, 접근성도 살핀다. 또한 어떤 절차는 정당한 목적을 가진다고 구분한다. 따라서 단계가 많다는 이유만으로 폐지를 요구하지 않는다. [OECD 보고서](https://www.oecd.org/en/publications/fixing-frictions-sludge-audits-around-the-world_5e9bb35c-en.html)

NSW 정부의 민원 처리 안내는 이용 단계 작성, 자료 수집, 시간과 진행 측정, 이용 경험 평가, 접근성과 형평성 확인, 결과 분석, 개선안 설계의 일곱 단계를 제시한다. 개선 후에는 다시 측정한다. 이 방법을 국내 절차에 적용할 때도 이용자의 목표와 관찰 범위를 먼저 정한다. [NSW 민원 처리 안내 29쪽](https://www.nsw.gov.au/sites/default/files/2026-04/reducing-sludge-in-complaint-handling.pdf)

국민권익위는 민원 발생 현황, 주요 키워드, 급증 민원을 분석한다. 주간·월간 「국민의 소리」와 주제별 분석을 제도개선의 발굴원으로 활용한다. 공개된 동향보고서는 개인이 시작할 수 있는 자료다. [민원 빅데이터 분석 개요](https://www.acrc.go.kr/menu.es?mid=a10104050100)

행정규제기본법 제7조의 분석 항목도 점검 질문으로 쓸 수 있다. 필요성, 목적 달성 가능성, 대체 수단, 중복 규제, 비용과 편익, 중소기업 영향, 내용의 명료성, 구비서류와 처리절차 등을 확인한다. 이 조항의 적용 범위는 중앙행정기관의 규제 신설·강화 등에 관한 것이다. 모든 정책에 같은 작성 의무가 있다고 확대하지 않는다. [행정규제기본법 제7조 시행 2026년 5월 12일](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1032109827)

감사원 감사결과는 추가 조사 경로다. 이번 웹 조회에서는 홈페이지 본문을 판독하지 못했다. 개별 감사결과나 반복 지적을 확인했다고 기록하지 않는다. 민원 빅데이터 대시보드도 본문 판독이 제한돼, 우선 권익위가 공개한 보고서와 의결서를 사용한다. 경로별 확인 범위는 [조사 자료 목록](discovery-sources.json)에 보관한다.

## 반복 민원에서 문제를 찾는 방법

1. 한 분야와 비교 기간을 정한다. 예를 들어 한 절차의 최근 6개월 동향을 본다.
2. 자료의 대상 기간, 수집 창구, 제외 항목과 집계 단위를 적는다.
3. 사례를 같은 원인으로 묶는다. 동일 요구의 반복 제출과 서로 다른 원인을 구분한다.
4. 발생 장소·시기·기관이 다른 독립 사례를 찾는다. 같은 보도나 보고서를 인용한 자료는 하나의 근거로 센다.
5. 빈도와 피해의 크기를 따로 기록한다. 민원이 적어도 접근하기 어려운 이용자의 문제가 빠졌을 수 있다.
6. 현재 규정, 기관 설명, 이미 진행 중인 개선 조치를 확인한다.

권익위 「국민의 소리」 제878호는 2026년 9월 21일부터 27일까지의 동향을 다룬다. 수집된 분석 데이터에서 교통단속민원을 제외한다고 명시한다. 따라서 다른 집계와 비교하기 전에 범위를 맞춰야 한다. 이 보고서는 특수교육교원 정원 확보 요청 등을 문제 후보의 단서로 제공한다. 민원 내용 자체를 실제 정원 미달의 증거로 사용하지 않는다. [제878호 원문](https://www.acrc.go.kr/boardDownload.es?bid=1009&list_no=119416&seq=1)

민원 증가율을 계산할 때는 같은 기간·수집 기준을 사용한다. 작은 분모, 접수 창구 변경, 집단 제출, 계절적 요인을 먼저 검토한다. 자료에 고유 신청자 수가 없으면 접수 건수를 사람 수로 바꾸지 않는다.

## 규칙을 비교해 문제를 찾는 방법

**기관 간 비교**에서는 같은 업무를 처리하는 두 기관을 고른다. 대상자의 조건, 적용 법령, 기준일을 맞춘다. 구비서류, 수수료, 방문 필요 여부, 처리 단계와 안내를 비교한다. 차이가 있으면 위임 범위와 지역별 조건을 확인한다. 다른 결과가 있다는 사실만으로 차별이나 위법을 확정하지 않는다.

**기준값 전후 비교**에서는 소득·자산·규모·기간 등 한 조건만 바꾼 두 사례를 만든다. 해당 조건의 정의와 예외를 먼저 확인한다. 지원액이나 부담이 어떻게 달라지는지 같은 기준으로 계산한다. 가상 사례는 가상이라고 적고 실제 신청자 정보나 실제 제출 내역으로 사용하지 않는다.

**목적과 수단의 비교**에서는 기관이 밝힌 목적을 먼저 적는다. 현재 절차가 그 목적을 달성하는 근거와, 부담이 더 작은 대체 수단을 찾는다. 인증, 안전 확인, 부정수급 방지 등 필요한 절차도 검토한다. 근거가 공개돼 있지 않으면 보유자료를 청구하거나 설명을 요청한다. 자료가 보이지 않는다는 이유로 목적이나 검토가 없었다고 결론내리지 않는다.

**개정 전후 비교**에서는 조문만 비교하지 않는다. 시행일, 경과조치, 예외와 하위 지침을 함께 본다. 해외 사례는 비교 가설을 만드는 데 쓴다. 대상자와 행정 체계가 다른 제도를 곧바로 국내 대안의 효과 증거로 사용하지 않는다.

## 실제 절차의 부담을 측정하는 방법

이용자 한 유형과 완료할 목표 하나를 정한다. 신청 화면 밖에서 필요한 준비도 단계에 넣는다. 자료 찾기, 서류 발급, 이동, 대기, 재입력, 보완요구와 결과 확인을 기록한다. 관찰한 사실과 이용자가 설명한 경험은 구분한다.

| 측정 항목 | 기록할 값 | 해석할 때 주의할 점 |
| --- | --- | --- |
| 단계와 반복 | 화면, 입력 항목, 필요한 서류, 방문, 같은 정보의 재입력 | 화면 수와 실제 이용자의 행동 수를 구분 |
| 시간 | 실제 작업시간, 대기기간, 재작업시간 | 동시에 진행한 일을 중복 합산하지 않음 |
| 비용 | 수수료, 이동비, 서류 발급비 | 시간의 금액 환산은 단가와 가정을 별도로 표시 |
| 이해와 예측 가능성 | 이해하기 어려운 표현, 모순된 안내, 다음 단계의 불명확함 | 개인의 느낌과 관찰 가능한 안내 내용을 구분 |
| 접근성 | 온라인·방문 경로, 기기 조건, 장애·언어 등 이용 조건 | 본인이 사용하지 않은 경로는 미확인으로 남김 |
| 실패와 재작업 | 오류 메시지, 보완요구, 실패한 단계와 재시도 | 인증 실패나 기기 문제를 제도 전체의 원인으로 단정하지 않음 |

한 번의 이용 기록은 사례 증거다. 전체 이용자의 평균이나 구조적인 문제라고 일반화하려면 비교 가능한 추가 사례와 자료가 필요하다. 기관 내부 업무나 처리시간은 외부 화면만으로 추정하지 않는다.

컴퓨터 사용으로 화면과 안내를 관찰할 수 있다. 실제 신청, 결제, 취소나 민원 제출은 조사 목적으로 임의 실행하지 않는다. 가상의 개인정보를 실제 신청 양식에 넣어 제출하지 않는다. 실제 이용 경로를 재현할 때도 해당 행위의 실행 범위를 확인한다.

## 후보를 조치할 문제로 바꾸는 기준

후보는 [문제 후보 기록 양식](issue-candidate.example.md)에 적는다. 후보 단계는 후보, 검증 중, 조치 준비, 보류, 제외로 관리한다. 근거 상태는 `pending`, `confirmed`, `conflict`, `context_only`로 별도 기록한다.

조치 요구를 준비할 때는 현재 규칙과 구체적인 사례, 문제와 연결되는 근거, 기관의 설명과 반대 근거, 담당기관, 요구할 변경을 확보한다. 자료가 부족하면 필요한 자료와 검증 질문을 적는다. 정보공개청구는 이 검증 단계에서도 사용할 수 있다.

이미 개선됐거나 비교 조건이 다른 사례는 제외한다. 자료가 부족하거나 시행 결과를 기다려야 하는 후보는 보류하고 다시 볼 조건을 적는다. 제출을 준비하는 절차는 새 `case_id`로 만들고 해당 `issue_id`에 연결한다. 후보 양식 자체를 현재 장부의 `add` 입력으로 사용하지 않는다.

## 개인 운영을 위한 첫 실행안

아래 수량은 시작할 때 사용할 작업량 제안이다. 방법의 효과가 입증된 기준이나 자동 실행 일정은 아니다.

1. 최근 공개 민원 동향 4개와 관련 제도개선 의결서 3개를 읽는다.
2. 각 자료에서 문제의 원인, 현재 규칙, 담당기관, 이미 예정된 변경을 추출한다.
3. 후보를 최대 10개 적고 같은 원인과 기존 개선안을 대조한다.
4. 근거를 확보하기 쉬운 비교 사례 2개와 실제 절차 1개를 검증한다.
5. 구체적인 변경을 요구할 수 있는 문제를 최대 3개 선정한다.
6. 나머지는 제외 또는 보류 이유와 다시 확인할 조건을 기록한다.

발굴 과정도 점검한다. 읽은 자료 수보다 원문 검증을 통과한 후보의 비율, 제외한 이유, 확인하지 못한 이용자 유형을 본다. 이후 실제 변경과 이용 부담의 감소를 추적한다. 현재 반복 조회나 후보 자동 수집 일정은 생성하지 않았다.

에이전트가 같은 방법을 실행할 때는 [발굴 실행 지침](discovery-runbook.md)을 따른다. AI는 자료 추출, 중복 후보 정리, 규칙 비교와 검증 질문 작성을 지원한다. 요약만으로 문제를 확정하거나 새로운 민원을 전송하지 않는다.
