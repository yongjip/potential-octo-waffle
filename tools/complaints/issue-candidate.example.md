# 문제 후보 기록 양식

이 양식은 발굴한 문제를 검증하기 위한 로컬 기록이다. 실제 값으로 바꿔 `data/complaints/discovery/`에 보관한다. 개인 사례와 원문 증거는 Git에서 제외한다. 이 양식은 `tracker.mjs add`의 입력 형식이 아니다.

## 문제와 범위

- 문제 식별자 `issue_id`:
- 문제를 설명하는 한 문장:
- 이용자 유형과 완료할 목표:
- 분야와 담당기관:
- 적용 대상과 비교 조건:
- 법령·지침의 버전과 시행일:
- 사건 발생일 또는 분석 대상 기간:
- 후보 단계: 후보 / 검증 중 / 조치 준비 / 보류 / 제외
- 근거 상태: pending / confirmed / conflict / context_only

## 근거와 관찰

| 출처 또는 파일 | 작성기관 | 자료의 기준일 | 확인일 | 원문 위치 | 확인한 사실 | 아직 확인할 항목 |
| --- | --- | --- | --- | --- | --- | --- |
| 입력 필요 | 입력 필요 | 입력 필요 | 입력 필요 | 입력 필요 | 입력 필요 | 입력 필요 |

공식 원문이나 회신, 기준일, 출처와 원문 위치가 있어야 사실을 confirmed로 기록한다. 보도, 요약과 자신의 해석은 별도 기록한다.

| 단계 또는 비교 항목 | 사례 A | 사례 B | 시간·비용·부담 | 관찰 방법과 한계 |
| --- | --- | --- | --- | --- |
| 입력 필요 | 입력 필요 | 입력 필요 | 입력 필요 | 입력 필요 |

## 시행 전 후보의 추가 기록

이미 시행된 문제만 다룰 때는 해당 없음으로 남긴다. 아래 항목은 원안과 예상 영향을 검토하기 위한 기록이다.

- 대상 유형: 정부 계획 / 정부 입법예고 / 국회 법률안 / 행정예고 / 지방 조례·규칙 / 예산·사업 / 구매 계획
- 발행기관과 공식 식별자: 의안번호·공고번호·사업번호 등
- 원문에 표시된 현재 단계와 확인일:
- 현행 규칙·사업 조건과 제안 문구의 변경 위치:
- 원안·수정안·재예고·대안의 공식 연결 근거:
- 원문·첨부 버전, 해시와 이전 버전의 위치:
- 예상 영향을 받는 대상과 가상 사례의 조건:
- 예상 영향의 근거·가정·불확실성:
- 필요성·보호 장치·예외·대안을 뒷받침하는 근거:
- 의견 제출처·방법·참여 자격:
- 실제 의견 마감일·시각과 근거: 시각이 없으면 미확인
- 다음 심사·결정 예정일과 근거:
- 제안된 시행일·경과조치: 확정 여부 별도
- 내부 준비일·확인일:
- 심각성, 긴급성, 되돌리기 어려움의 각각의 판단:
- 요구할 수정 위치·문구 또는 대안:
- 최종안에서 확인할 반영 조건과 시행 후 확인할 결과:

추진 사실, 예상 영향과 정책 판단을 각각 기록한다. 예정된 피해를 실제 피해로 표시하지 않는다. 제출 내역은 별도 `case_id`에 연결한다.

## 검증 질문

- 현재 규칙과 실제 처리는 어떻게 다른가:
- 두 사례의 비교 조건은 같은가:
- 기관이 설명하는 목적과 이유는 무엇인가:
- 필요한 절차일 수 있다는 반대 근거는 무엇인가:
- 같은 사례나 자료를 중복 집계했는가:
- 이미 시행됐거나 예정된 개선은 무엇인가:
- 문제의 원인이 규칙, 집행, 안내, 시스템 중 어디에 있는가:
- 부족한 자료와 확보할 방법은 무엇인가:

## 조치와 다음 확인

- 요구할 변경과 대안:
- 실제 변경을 확인할 완료 조건:
- 영향·반복성·근거·변경 가능성의 판단과 이유:
- 기존 `issue_id` 또는 `case_id`와의 관계:
- 다음 행동과 내부 확인일:
- 제외·보류 이유와 다시 볼 조건:

실제 제출 절차를 준비할 때는 별도 사건을 만든다. 접수번호와 처리 상태는 민원 장부에서 관리한다.
