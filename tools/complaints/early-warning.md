# 입법과 행정의 시행 전 문제를 찾는 방법

기준일: 2026년 10월 8일 KST

목표는 **법률·규칙·정책·사업이 확정되거나 집행되기 전에 변경안과 예상 영향을 검토하는 것**이다. 공개 계획에서 후보를 찾고, 원문에서 바뀔 내용을 확인하고, 의견을 낼 수 있는 시점에 구체적인 수정안을 준비한다. 이미 발생한 문제의 조사 방법은 [문제 발굴 조사 방법](discovery-research.md)을 따른다.

여기서 ‘사전 탐지’는 공개된 추진 사실을 확인하는 일이다. 추진 사실, 향후 영향에 대한 예상, 정책에 대한 판단을 각각 기록한다. 발의자와 기관에 관계없이 같은 기준을 적용한다. 공개되지 않은 의도나 모든 행위를 탐지할 수 있다고 가정하지 않는다.

## 먼저 조회할 공개 자료

| 단계·대상 | 공식 경로 | 기록할 내용 | 확인 범위와 한계 |
| --- | --- | --- | --- |
| 정부의 입안 계획 | [정부입법계획](https://opinion.lawmaking.go.kr/lmSts/govLmPln) | 법령명, 소관부처, 계획 식별자, 추진단계와 날짜 | 목록과 한 상세 화면을 확인. 계획은 확정 조문이나 통과 사실이 아님 |

통합 행정예고와 지방 입법예고의 수록 한계는 각 목록에 안내돼 있다. 따라서 통합 포털에서 검색 결과가 없다는 이유로 해당 공고가 없다고 판단하지 않는다. [행정예고 수록 범위](https://opinion.lawmaking.go.kr/gcom/admpp), [지방 입법예고 수록 범위](https://opinion.lawmaking.go.kr/gcom/sgLmPp/list)

[서울특별시의회](https://www.smc.seoul.kr/main/index.do)는 의사일정, 의안정보, 입법예고, 심사 검토보고서와 예산·재정 자료 메뉴를 제공한다. 이번에는 메뉴를 확인했다. 개별 조례안과 회의 안건은 아직 검토하지 않았다. 지역을 확장할 때 해당 지방의회의 공개 경로를 추가한다.

기관의 업무계획·보도자료·공청회 공고에서도 단서를 찾는다. 이후 원안을 찾고 그 문서의 효력과 시행 조건을 확인한다. 보도자료의 ‘추진’ 표현을 실제 실행 또는 확정으로 바꾸지 않는다. [조사 자료와 확인 범위](early-warning-sources.json)에 조회 결과를 기록했다.

## 변경 내용에서 검토 후보를 고르는 기준

아래 기준은 개인 운영을 위한 검토 질문이다. 해당 문구가 있다는 사실만으로 불합리하거나 위법하다고 확정하지 않는다.

| 변화 신호 | 원문에서 검증할 질문 | 필요한 비교·반대 근거 |
| --- | --- | --- |
| 수집·조회·조사 권한 확대 | 대상·목적·자료 범위·기관 간 제공·보유기간·감독은 어떻게 정하는가 | 기존 권한과 실제 공백, 다른 법의 보호 장치, 부담이 작은 대안 |
| 의무·벌칙·제재 강화 | 위반 요건, 산정 분모, 상한·실제 부과 조건, 소명·불복은 명확한가 | 고의·과실, 규모별 가상 사례, 피해 방지 효과와 단계적 제재 |
| 자격·지원 대상 변경 | 조건 하나가 달라질 때 누가 제외되는가 | 정의·예외·경과조치, 같은 조건의 비교, 제도의 목적 |
| 비용·책임의 이전 | 비용을 누가 부담하며 부담에 상응하는 편익이 있는가 | 공적·민간 비용 구분, 비용추계, 이미 부담한 비용 |
| 절차·정보공개 축소 | 확인·통지·의견·이의제기 기회가 어떻게 바뀌는가 | 긴급성 근거, 적용 기간, 사후 점검, 다른 절차의 보완 여부 |
| 위임·재량 확대 | 핵심 조건을 누가 어떤 기준으로 정하는가 | 상위법 위임, 공개 지침, 적용 사례와 통제 수단 |
| 사업 신설·확대·민간위탁 | 기존 사업과 역할이 겹치는가. 목표와 책임이 측정 가능한가 | 사업 설명서, 수요 자료, 성과 기준, 서비스 중단 시 대응 |
| 구매 규격·참가 조건 변경 | 특정 방식·제품·규모 요구가 업무 목적에 필요한가 | 기능상 필요, 호환·안전 조건, 대체 규격과 경쟁 가능한 범위 |

검색은 분야·기관·지역과 변화 신호를 함께 사용한다. 예시 단어는 신설, 의무화, 제한, 환수, 과징금, 수집, 제공, 위탁, 지정, 제외, 재입법예고다. 이 단어만으로 후보를 확정하지 않는다. 제목에 단어가 없을 수 있으므로 선정 분야의 신규 목록과 첨부 변경도 확인한다. 키워드에 잡히지 않은 자료를 일부 검토해 누락 원인을 기록한다.

## 계획부터 확정·집행까지 연결하기

1. 새 계획·예고·발의를 발견하면 공식 식별자와 원문을 보관한다.
2. 현재 규정과 제안 문구를 대조한다. 바뀌는 조문·기준·절차를 표시한다.
3. 예상 영향은 가정과 계산 조건을 붙여 기록한다. 실제 피해와 구분한다.
4. 담당기관, 결정 단계, 의견 경로와 마감일을 확인한다.
5. 필요한 자료 요청과 수정 의견 초안을 함께 준비한다.
6. 재예고·수정안·위원회 대안·철회·의결 여부를 확인한다.
7. 최종 원문과 시행일, 경과조치, 실제 집행을 대조해 결과를 기록한다.

| 항목 | 기록 원칙 |
| --- | --- |
| 대상 식별자 | 의안번호, 공고번호, 사업번호 등 포털별 식별자와 발행기관을 묶음. 제목만으로 합치지 않음 |
| 문제 연결 | 같은 문제는 `issue_id`로 연결. 법률안, 시행령안, 사업 계획은 각각 별도 대상 |
| 단계 | 공개 계획 / 발의·예고 / 심사 / 확정·공포 / 시행·집행 / 철회·종료 등 원문 단계와 관찰일 보관. 유형에 따라 생략·반복 가능 |
| 버전 | 원문 URL, 게시일, 확인일, 첨부 해시, 비교 기준. 교체된 원문도 보존 |
| 후속 관계 | 재예고·수정안·대안의 공식 관계를 확인해 연결. 원안의 ‘대안반영폐기’ 표시는 대안 원문까지 검토 |
| 기한 | 의견 마감, 회의·결정 예정일, 시행일, 내부 확인일을 별도로 기록. 미확인 값은 비워 둠 |
| 판단 | 추진 사실의 근거 상태와 예상 영향·수정 필요성의 검토 상태를 분리 |

의안번호가 바뀐 대안은 새 원문으로 대조한다. 같은 공고의 첨부파일만 바뀌어도 다시 검토한다. 페이지에서 사라진 안건은 삭제·철회로 추정하지 않고 상태를 재확인한다. 회의 일정은 바뀔 수 있으므로 예정과 실제 의결을 구분한다.

## 의견 경로와 기한

예고 중에는 해당 공고가 정한 의견 경로를 먼저 사용한다. 의견은 **변경 위치 → 예상 문제 → 근거·조건 → 수정 문구 또는 대안** 순서로 쓴다. 정보공개청구로 근거 자료를 확보할 때도 의견 마감은 별도로 관리한다. 회신이 마감 전에 온다고 가정하지 않는다.

| 상황 | 준비할 조치 | 기한 확인 |
| --- | --- | --- |
| 정부 입법·행정예고 | 예고 의견, 필요한 기존 자료의 공개청구 | 공고의 접수기간·경로·마감 시각·변경 공고 |
| 국회 입법예고 | 소관위원회에 조문별 의견 | 국회 공고의 기간과 진행 상태. 예고 종료 뒤의 제출 경로는 별도로 확인 |
| 지방 집행기관·의회 예고 | 해당 예고의 제출처에 조례·규칙 의견 | 집행기관과 의회 공고의 대상·기간·경로를 각각 확인 |
| 사업·예산·구매 계획 | 목적·선정 기준·성과 근거 질문, 적용 가능한 의견 절차 | 일반 시민의 의견 경로와 참여 자격 확인. 사전규격의 업체 의견 절차를 일반 민원과 구분 |
| 이미 확정·시행 | 최종안 대조 후 적용·개선·피해 구제의 경로 선택 | 시행일·경과조치와 해당 절차의 기한 확인 |

행정절차법 제43조는 특별한 사정이 없을 때 입법예고를 40일 이상, 자치법규는 20일 이상으로 정한다. 국회 규칙은 일부개정안 10일 이상, 제정·전부개정안 15일 이상을 정하며 단축·연장 규정도 둔다. 두 절차의 기간을 혼용하지 않는다. 실제 작업 기한은 최신 공고로 확인한다. [행정절차법 제43조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1032794171), [국회 입법예고에 관한 규칙 제4·5조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=57516)

행정예고에는 정책·제도·계획의 예고 대상과 예외가 별도로 정해져 있다. 이번에 확인한 행정절차법 원문 제46조는 20일 이상, 긴급한 필요에 따른 단축 때 10일 이상을 규정한다. 적용 범위와 예외를 확인한 뒤 판단한다. 짧은 공고 기간만으로 위법을 확정하지 않는다. [제46조와 예외](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020128385), [법률 제18748호 원문 18쪽](https://www.law.go.kr/LSW/lsPdfPrint.do?ancYnChk=0&bylChaChk=N&efGubun=Y&efYd=20220712&joAllCheck=Y&joEfOutPutYn=on&lsiSeq=239291&mokChaChk=N)

공고의 날짜와 상세 본문이 다르면 `conflict`로 남기고 기관 공고와 변경 공고를 확인한다. 마감 시각이 없으면 자정 마감으로 채우지 않는다. 내부 준비일은 실제 마감보다 앞서 정하되 법정기한으로 표시하지 않는다.

## 자동화에 넣을 조회·변경·알림 기준

아래는 후속 구현 설계다. 현재 자동 수집·비교·알림 일정은 실행 중이 아니다.

1. 선정 분야의 신규·수정 목록을 조회한다. 마지막 성공 시점보다 앞선 기간도 겹쳐 조회해 지연 게시와 수정 공고를 확인한다.
2. 포털별 식별자와 기관을 기준으로 중복을 정리한다. 원문·첨부와 해시를 보관한다.
3. 기준 버전과 비교해 변경 위치, 대상, 요건, 숫자, 예외, 시행일을 추출한다.
4. 검토 질문과 반대 근거를 기록한다. 원문을 확보하지 못한 후보는 제목 수준의 단서로 남긴다.
5. 새 검토 후보, 중요 문구 변경, 마감 변경, 심사 진전, 철회·대안, 조회 실패를 구분해 알린다.
6. 마감일과 내부 확인일에 맞춰 다음 작업을 정한다. 실제 외부 제출은 구체적인 문안과 경로가 정해진 사건에 연결한다.

조회 실패는 ‘신규 없음’으로 기록하지 않는다. 출처별 마지막 성공 시점, 접근 실패와 조사 범위를 알림에 포함한다. API 설명의 ‘실시간’ 표시는 실제 수집의 최신성 보장이 아니다. 사용 가능한 공식 API·문서 조회를 우선 사용하고 동적 화면은 computer use로 확인한다. 인증키 발급·활용신청·유료 서비스 연결은 실행 전 별도로 다룬다.

추천 작업 주기는 예고·발의 목록을 매일, 초기 계획·사업 목록을 주간으로 확인하는 방식이다. 검토 중인 사안은 실제 마감과 결정 일정에 맞춰 더 자주 확인한다. 마감 7·3·1일 전 점검은 내부 준비 기준으로 제안한다. 현재 일정 생성이나 구독 신청은 하지 않았다.

알림에는 대상과 변경 위치, 예상 영향의 가정, 근거 수준, 실제 마감, 다음 행동을 넣는다. 중요도와 긴급도를 분리한다. 우선 검토는 영향·되돌리기 어려움·근거·수정 가능성을 함께 판단한다. 평상시 집중 검토는 3건 이내로 두고, 중대한 신규 신호가 생기면 기존 우선순위를 다시 정한다.

## 예방 성과를 확인하는 기준

의견 접수와 회신은 활동 기록이다. 예방 성과는 최종 원문에서 요구한 수정이 반영됐는지, 범위·조건·부담이 어떻게 바뀌었는지, 시행 후 예상 문제가 줄었는지 확인해 기록한다. 철회·수정이 본인의 의견 때문이라고 말하려면 그 연결 근거가 필요하다. 반영 원인이 미확인이면 변경 사실과 원인 미확인을 함께 남긴다.

[문제 후보 양식](issue-candidate.example.md)의 사전 탐지 항목과 [발굴 실행 지침](discovery-runbook.md)을 사용한다. 실제 기록은 Git에서 제외되는 `data/complaints/discovery/`에 둔다. 예고 의견과 자료 청구는 각각 `case_id`를 만들고 같은 `issue_id`에 연결한다. 현재 민원 장부가 지원하지 않는 제출 유형·포털은 형식을 먼저 확장해야 한다.
