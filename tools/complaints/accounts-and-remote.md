# 민원 계정 입력과 원격 사용 준비

기준일: 2026년 10월 8일 KST

**사용자가 회원가입을 하고, 가입한 계정의 아이디와 비밀번호를 로컬 입력 도구에 넣는다.** 도구는 네 포털의 값을 Git에서 제외된 `.env`에 저장한다. 원격 작업도 이 파일과 민원 장부가 있는 Mac에서 실행한다. 회원가입, 로그인 확인, 실제 민원 접수는 서로 다른 완료 단계다.

## 가입할 계정

| 제출 포털 | 사용할 계정 | 가입 진입점 | 공개 가입 화면 확인 범위 |
| --- | --- | --- | --- |
| 국민신문고 | 국민신문고 회원 | [회원 유형 선택](https://www.epeople.go.kr/nep/mfrnUser/mbrSelectPage.npaid) | 일반회원의 본인확인 단계. 간편인증·금융인증서·공동인증서·휴대전화 선택지 |
| 정보공개포털 | 정보공개포털 회원 | [회원가입](https://www.open.go.kr/mberSvc/mber/persionIn.do) | 개인(내국인) 선택 후 이용약관·개인정보 안내 단계 |
| 서울시 응답소 | 서울시 통합회원 | [서울시 회원가입](https://www.seoul.go.kr/member/join/regist01.do) | 일반회원의 필수 약관·개인정보 동의와 선택 정보 수신 항목 |

위 가입 진입점은 2026-10-08 공개 화면에서 확인했다. 본인확인과 가입 완료 절차는 사용자가 수행한다. 같은 날 사용자가 저장한 네 계정으로 실제 로그인을 확인했다. 서울시 통합회원으로 응답소를 사용할 수 있으므로 응답소 전용 계정을 추가로 만들 필요는 없다. 기존 계정이 있으면 같은 계정을 사용한다. 새 계정에 과거 비회원 제출 내역이 자동 연결되는지는 별도 확인 대상이다.

## 저장 위치와 권한

| 경로 | 내용 | 권한 |
| --- | --- | --- |
| `data/complaints/auth/.env` | 네 계정의 아이디와 비밀번호 | 소유자만 읽고 쓰는 `600` |
| `data/complaints/auth/runtime.json` | 실행 Mac 이름, 브라우저, 대상 포털 | `600` |
| `data/complaints/auth/` | 비공개 계정 저장 폴더 | 소유자만 접근하는 `700` |
| [`.env.example`](.env.example) | 빈 값과 환경변수 이름 | 공개 예시. 실제 값 입력 금지 |

기존 `.gitignore`는 `data/complaints/`와 실제 `.env`를 제외한다. 입력 도구도 Git 제외 여부와 추적 여부를 확인한다. 파일이 Git에 올라갔거나, 다른 사용자가 읽을 수 있거나, 심볼릭 링크·하드 링크를 사용하면 저장과 읽기를 거부한다. 동시 저장은 잠금 파일로 차단한다.

`.env`는 **암호화된 저장소가 아닌 평문 파일**이다. 파일 권한은 다른 로컬 사용자의 접근을 줄인다. 공개 저장소, 공개 백업, 채팅, 로그에 이 파일을 복사하지 않는다. 다른 Mac으로 Git 브랜치를 가져와도 실제 로그인 정보와 민원 장부는 따라가지 않는다.

## 사용자가 입력할 때

저장소 루트에서 실행한다. 초기화는 실행할 Mac 이름을 지정한다. 아래 명령은 명령을 실행하는 Mac을 선택한다.

```bash
node tools/complaints/accounts.mjs init --host="$(node -p 'require("node:os").hostname()')"
node tools/complaints/accounts.mjs store --portal=all
node tools/complaints/accounts.mjs status
```

`init`는 기존 세 포털 설정에서도 사용할 수 있다. 기존 계정 파일의 내용을 보존하고 입법센터의 빈 변수 두 개를 추가한다. 실행 Mac 설정은 유지한다. 입법센터 변수가 이미 있으면 그 값을 유지한다.

`store`는 국민신문고, 정보공개포털, 서울시 통합회원, 국민참여입법센터 순서로 입력을 받는다. 각 계정에서 아이디, 기존 비밀번호, 비밀번호 확인을 입력하고 각각 Enter를 누른다. **아이디와 비밀번호 모두 화면에 표시하지 않는다.** 비밀번호가 일치한 계정부터 저장한다. 도중에 취소하면 앞서 저장한 계정은 유지한다.

한 계정만 입력하거나 로컬 저장 값을 바꿀 때는 해당 포털만 선택한다. 이 명령은 포털의 비밀번호를 바꾸지 않는다.

```bash
node tools/complaints/accounts.mjs store --portal=epeople
node tools/complaints/accounts.mjs store --portal=open_go_kr
node tools/complaints/accounts.mjs store --portal=seoul_eungdapso
node tools/complaints/accounts.mjs store --portal=lawmaking
```

| 계정 | 아이디 변수 | 비밀번호 변수 |
| --- | --- | --- |
| 국민신문고 | `COMPLAINTS_EPEOPLE_ID` | `COMPLAINTS_EPEOPLE_PASSWORD` |
| 정보공개포털 | `COMPLAINTS_OPEN_GO_ID` | `COMPLAINTS_OPEN_GO_PASSWORD` |
| 서울시 통합회원 | `COMPLAINTS_SEOUL_ID` | `COMPLAINTS_SEOUL_PASSWORD` |
| 국민참여입법센터 | `COMPLAINTS_LAWMAKING_ID` | `COMPLAINTS_LAWMAKING_PASSWORD` |

값은 명령 인수나 채팅에 넣지 않는다. `.env`를 `source`로 실행하지 않는다. 저장 도구는 JSON 형식의 따옴표를 사용하고 `$`, 백틱, 역슬래시 등을 문자 그대로 보존한다. `status`는 저장 여부만 출력한다. 아이디나 비밀번호는 출력하지 않는다.

```bash
node tools/complaints/accounts.mjs doctor
node --test tools/complaints/accounts.test.mjs
```

`doctor` 종료 코드 `0`은 네 계정의 값이 저장됐다는 뜻이다. `2`는 빈 계정이 남았다는 뜻이다. `1`은 저장 위치·권한·형식·실행 Mac 점검 실패다. 종료 코드 `0`도 실제 로그인이나 민원 접수를 증명하지 않는다.

최초 세 포털 준비에서는 현재 작업 Mac에 빈 파일을 생성했다. 계정 도구와 기존 장부의 테스트 17개를 통과했다. 가짜 계정으로 실제 터미널 입력을 점검했고, 아이디·비밀번호가 출력되지 않는 것과 특수문자 보존을 확인했다. 당시 computer use 세션에서 로컬 모듈을 불러와 빈 계정의 저장 여부를 확인했다. 실제 계정 값은 입력하지 않았다.

## 로그인 확인 결과

2026년 10월 8일 네 계정의 저장된 아이디·비밀번호로 각각 한 번 로그인해 성공했다. 국민참여입법센터는 기존 로그인 세션을 종료한 뒤 저장된 계정 정보를 검증했다. 아래 문구는 당시 인증 후 화면에서 확인한 표시다. 다음 실행에서는 현재 화면을 다시 확인한다.

| 포털 | 확인한 로그인 결과 |
| --- | --- |
| 국민신문고 | `나의 신문고`, `로그아웃` 표시 |
| 정보공개포털 | 보안문자 입력 후 `마이페이지`, `로그아웃` 표시 |
| 서울시 응답소 | 통합회원의 비밀번호·보안문자 로그인 후 응답소에 복귀. `로그아웃`, `내정보 변경` 표시 |
| 국민참여입법센터 | 저장된 계정 정보로 새 로그인 후 `마이페이지`, `로그아웃` 표시 |

정보공개포털과 서울시의 보안문자는 사용자가 현재 화면의 입력을 직접 지시한 뒤 에이전트가 읽고 입력했다. 같은 요청을 다시 확인하지 않았다. 이 기록은 해당 로그인 단계의 실행 근거이며, 앞으로의 모든 보안문자나 다른 작업을 일괄 허용하는 설정은 아니다.

계정 도구의 `browser_session=not_verified`는 도구가 브라우저를 검사하지 않는다는 뜻이다. 이 값을 로그인 결과로 바꾸거나 `runtime.json`을 임의로 수정하지 않는다. 날짜가 있는 로그인 결과와 화면 증거는 비공개 `data/complaints/auth/login-checks/`에 별도로 저장한다. [운영 교훈](lessons-learned.md)과 [로그인 확인 절차](remote-runbook.md#password-login-checks)를 참고한다.

## 원격 실행 방식

사용자가 선택한 방식은 연결된 Mac 원격 세션이다. 계정 파일과 민원 장부를 한 Mac에 두고, 원격에서 그 Mac의 작업을 지시한다. 실행 Mac 이름이 설정과 다르면 도구는 비밀번호를 읽기 전에 중단한다. 다른 Mac에서 실행하려면 그 Mac에 별도 비공개 저장소를 준비한다.

OpenAI 공식 안내는 원격에서 실행할 호스트와 작업 공간을 선택하는 방식과, 연결된 호스트에서 코드가 실행되는 방식을 설명한다. 이는 민원 포털에 로그인이 됐다는 증거와는 별도다. [OpenAI 원격 작업 안내](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)

로그인 이후에는 같은 Mac의 브라우저 세션을 사용한다. 인증이 만료되거나 추가 본인확인이 나오면 그 단계를 처리한 뒤 이어서 작업한다. **로그인 성공만으로 완전 무인 제출이 보장되지는 않는다.** 네 포털의 로그인은 확인했지만 개별 사건 조회와 실제 접수는 별도 검증 대상이다. 입법센터의 계정 저장 지원과 기존 세 민원 포털을 지원하는 장부는 별도 기능이다.

실행 순서와 비밀번호를 출력하지 않는 로딩 방법은 [원격 실행 지침](remote-runbook.md)을 따른다. 기존 사건 조회·폼 입력·접수증 보관은 [computer use 실행 지침](computer-use.md)을 따른다.

## 확인한 약관과 적용 범위

국민신문고의 공개 이용약관 제12조 제6항은 사전 승낙 없는 자동 가입·로그인·콘텐츠 접근과 자료 처리를 제한한다고 표시한다. 정보공개포털의 가입 약관 제13조 제4항 제8호는 사전 허락 없는 자동 로그인을 제한한다고 표시한다. 이는 2026-10-08에 읽은 화면의 관찰이다. [국민신문고 이용약관](https://www.epeople.go.kr/nep/gdnc/TermsConditions.npaid), [정보공개포털 가입 약관](https://www.open.go.kr/mberSvc/mber/mberSbscrbAge.do)

사용자는 이 문구를 작업 중단 조건으로 쓰지 말라고 지시했다. 이 도구에는 포털 사전 허락을 요구하는 실행 차단을 넣지 않았다. 계정 저장과 로그인용 읽기만 구현한다. 사용자가 직접 가입하므로 본인확인, 약관 동의와 새 비밀번호 입력도 사용자가 수행한다. 이후 특정 민원 제출 권한은 최종 기관·본문·개인정보·첨부가 정해진 실제 제출 건별로 판단한다.
