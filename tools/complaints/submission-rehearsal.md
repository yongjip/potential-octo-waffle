# Rehearse a reviewed complaint before filing

Canonical language: English. This procedure prepares institution-specific petitions, audit reports and requests for existing records. It reduces avoidable authentication, version, routing and duplicate-submission work. Read [computer-use.md](computer-use.md), [remote-runbook.md](remote-runbook.md) and the [lessons](lessons-learned.md) first.

## Prepare the reviewed envelope

1. Replay tracker events and read the accepted body of every related case. Keep new policy demands separate from old unanswered questions.
2. Freeze the title, clean body, recipient, procedure, questions, public visibility and necessary attachments. Exclude internal review notes, credentials and diagnostic logs.
3. Review the sources, arithmetic, scope, tone and institutional authority independently. Record the actual reviewer scope. A constructed official-reader review is not an official decision or a measured acceptance probability.
4. Preserve earlier frozen versions. Give substantive body changes a new version and body hash. Use a dated current manifest for stale historical metadata without rewriting accepted delivery or old evidence.
5. Keep a ready petition independent of unavailable recipient statistics, another petition's reply or an unpublished future recruitment notice. Recheck a future example when its official notice is available.

Use short, descriptive filenames for outgoing text and attachments. Use the recipient's language. Exclude internal task labels, revision numbers and review-status labels from the filename, cover and footer. Preserve version history privately and update current links and attachment metadata. Renaming alone preserves the file hash; editing a cover or footer requires a new hash, a content comparison and visual inspection before replacing the selected attachment.

## Rehearse the live form

1. Confirm the official origin and the execution host. Load only the destination's stored credential pair through the supported local adapter. Print presence and result flags only.
2. Preserve a useful existing draft and reuse an authorised session. Recheck the original case list for a duplicate before opening a new request.
3. Open the correct procedure. Read required fields, current character/byte limits, permitted file types, size/count limits and privacy choices.
4. Fill the reviewed title and complete body through supported computer-use APIs. Compare the full entered value with the frozen packet, including newlines. A visible counter or partial screenshot is insufficient.
5. Select necessary attachments with the documented file-chooser flow. Recheck the displayed filename and any validation message. Keep local file hash, selected-file observation and accepted server attachment distinct. An empty adapter FileList alone does not prove failure when the actual input displays the selected filename.
6. Save dated private evidence and a current result matrix. Mark each route as not inspected, authentication required, input checked, attachment selected, review reached, submission uncertain or acceptance verified. Do not describe a partial rehearsal as a completed end-to-end submission test.
7. Stop a rehearsal before registration, server-side draft saving or final acceptance. Do not create test complaints. A live session or CSRF token may expire; verify the current form again at execution.

Apply the current tool's confirmation rules to the actual pending step. Routine authorised sign-in and document preparation do not require a generic extra approval. A newly displayed CAPTCHA or binding agreement can require action-time confirmation even after general delegation. Save and mark the actual pending page, ask once for that concrete step and continue independent work. Do not weaken security protections to recover a failed upload.

If an upload or observation stalls, inspect the current control and outcome before retrying. Read the tool's applicable troubleshooting guide. A long interruption does not establish a permission, cookie, network or session-expiry cause. Reacquire current state and check whether the earlier action already took effect.

If the browser adapter cannot observe a page, inspect the matching native browser window through the same computer-use tool. A real draft-loading dialog or an inactive task tab can be visible there. Resolve only the observed blocker, then inspect the intended page again. A successful recovery does not prove the cause of earlier adapter failures.

Before refreshing an unsaved form, verify an exact local backup of its title, body and selected source files. Check whether a fresh server page still shows authentication. Client-side text on an old form is insufficient. Restore the reviewed fields and attachments after an intentional refresh. If automatic approval review rejects an action, report its reason, preserve the form and establish a safe recovery before retrying. Do not change security settings or use an indirect action to bypass the rejection.

An editable existing body is different from an additional-message function. Record the exact case state and observed route. Freeze and review the combined amendment, keep the old body as an exact prefix, and track original and supplemental question numbers separately. Preserve historical delivery evidence. Rehearse before the final modify/save control; if the amendment succeeds later, verify the saved complete body under the same receipt. Do not also file its fallback as a separate request.

The e-People municipal case inspected on 2026-10-11 was in the application/receipt stage and exposed `수정`. Its current edit form allowed both body changes and file additions. This dated observation does not establish that editing remains available after assignment. Preserve the original body as an exact prefix and explain when a new proposal refines an earlier option. Keep the accepted case valid while a separate amendment manifest records a pending save; do not downgrade the original receipt to an uncertain new filing. After the save confirmation, verify the same receipt and original application time, the complete amended body, paragraph spacing and downloaded attachment bytes. Record supplemental questions and update the existing monitored case. See the [municipal amendment lesson](lessons-learned.md#lessons-from-amending-a-municipal-petition-on-2026-10-11).

## Execute without unnecessary waiting

Once a reviewed envelope and the current route are ready, use the user's authorised execution scope. An internal target date is not a waiting requirement. Independent institutions may proceed without each other's replies. Submit deadline-bound reports before their official cutoff.

Immediately before the one final submission attempt, create a prepared child case if necessary and persist `submission_unknown`. Then submit once. Verify the accepted receipt, complete saved body, actual assignment and displayed deadline. Preserve primary evidence and append the result. If the outcome is uncertain, query the list before retrying. Never promote an uploaded filename, filled form or success-looking navigation into a confirmed receipt.

## Split council reports by the decision being requested

Separate topics when their decision, evidence and completion criteria differ. Keep one question and one matching attachment per report. State which other topics have separate reports. Preserve the earlier combined packet and mark it superseded; do not file it as an additional report.

For an entry-criteria report, compare the same estimated take-home income's cumulative savings with the same notice's actual payment requirement. Keep income, saving years and other funding assumptions fixed across saving-rate rows. This compares institutional criteria; it must not create a minimum-income or savings-history requirement for applicants. State the original assessment-income definition and the take-home conversion assumptions.

For a support-effects report, compare annual funding-cost savings using the same valuation assumptions across deposit amounts. Separate the price advantage and the interest advantage. Do not add the deferred principal as a benefit, treat an illustrative market ratio as a measured price, or call the calculation total government expenditure. Ask for alternative public-asset uses under the same period and target population.

For a childbirth-purchase report, compare deductions at the same conditional purchase stage. Use common chart axes and separate qualifying-birth groups. Label any fixed amount as an illustration. Equal deductions do not establish equal lifetime wealth or equal subsequent house-price gains. Preserve the exact qualifying date, including whether the announcement date counts, residence requirements and resale-return conditions.

Use a short body within the live limit and a subject-specific PDF. The two-page format used in this execution was enough for a chart, calculation assumptions, requests and references. Set a custom ReportLab Flowable's instance width and height after calling its base initializer; class attributes alone can leave a zero-height layout. Re-render every revised PDF and inspect all pages. Record final hashes before selection. If a selected file changes on disk, reselect it before upload.

After registration, open the owner's saved detail, compare the full body and download the actual attachment. Record the portal's actual identifier type. An audit-board ID is not automatically an ombudsman receipt number. An owner's general complaint menu may cover only the ombudsman procedure. Its empty list does not prove that audit reports are absent. A save confirmation and a subsequent registered-success alert are separate steps; wait for the actual outcome instead of clicking the final control again.

Check reader-visible layout separately from text integrity. Inspect the saved detail for paragraph gaps and separate numbered requests. A textarea can preserve every newline while the published page collapses them into one block. On the inspected council page, a single paragraph with `white-space: normal` ignored the saved plain-text newlines. Break tags entered through its normal edit form restored visible spacing. Keep the canonical prose separate from this portal-specific payload, count formatting characters against the live limit, and preserve titles, policy text and attachments. Use only the formatting controls or harmless line-break markup actually supported by the destination. Do not copy this council workaround to another portal or mutate the page's scripts or styles. Save and inspect a screenshot of the real server-saved result before reporting readable formatting.

The observed portal stripped hyphens from attachment names and rendered a middle dot as an HTML entity in a title. Map the server name to the frozen attachment hash. If a saved-title correction is rejected by automatic approval review, preserve the accepted case, request the specific correction once and continue unaffected reports. After the reply, reload the approved local envelope or use the exact approved value. Verify the specific corrected title, not merely a stale variable's self-consistency. Append a correction record when an earlier observation was wrong.

For contact corrections, distinguish the user's preferred correspondence email from account login IDs. Save the preference privately and verify each destination's contact field. Sensitive input values can be replaced with a redaction marker in the browser adapter, so a string comparison against that returned value can be false even when the real field is correct. Confirm the actual screen and the saved detail. For screenshot clips, use document coordinates: viewport rectangle plus scroll offset. Inspect the saved crop before embedding it. Keep complete private evidence separate from a cropped public-facing proof.

These steps verify filing, not committee assignment, a reply deadline or actual policy change. Keep unresolved questions and the next internal check date with each accepted report. A date in a plan creates no scheduled reminder.

## Complete executive-agency filings and preserve amendments

Use confirmed profile details for ordinary required fields without a generic approval request. Do not treat a required consent as a required text field. Under the current computer-use tool, each displayed CAPTCHA and binding agreement requires action-time confirmation. Bundle the actual pending confirmations when possible. Reuse confirmation for the same unchanged action; future general delegation does not remove a tool requirement. Read-only notices and routine input do not require that confirmation.

For custom radio controls, inspect the visible label when checking the input has no effect. The inspected e-People input had a one-pixel box beneath its visible label. Clicking the observed label changed the actual checked state. Verify the resulting selection before moving on. Do not invent click options or infer agreement from an attempted action. Decline unrequested location access if the browser displays that prompt. Its presence in one flow does not explain every failed action.

An existing Eungdapso edit must retain the accepted original as an exact prefix and preserve its receipt and original submission date. Append the reviewed supplement and add its questions to the ledger with distinct identifiers. Keep earlier question statuses and accepted evidence. Verify the new complete saved body, contact field and visible paragraph gaps. Do not create a replacement case when the amendment succeeds.

Persist an uncertain-submission record immediately before the one final attempt. A normal confirmation dialog can precede actual registration. Inspect the subsequent result without repeating the submit control. In the inspected e-People flow, the completion page's application-history link opened a list. Open the matching title from that list and compare the complete saved body. The saved text used `white-space: pre-wrap`; plain-text blank lines were readable. Eungdapso and information disclosure used visible break elements. These portals did not require the council's formatting payload.

For information disclosure, record both submission and institution-processing state. A portal receipt can coexist with an institution's pending-receipt state. Record a displayed processing date exactly, together with its observation time. Keep it separate from the next internal check date. Do not calculate an agency deadline for a petition that has not displayed one.

Retain historical rehearsals as dated evidence. Add a current execution manifest and point the preparation index to it instead of rewriting an old rehearsal as a filing. Check each full body against its frozen hash and inspect the real saved screenshot. Declining optional e-People contact consent disabled email and phone notices in this execution; track those cases through the website and do not claim that notification contact fields were saved.

## Review and file a tax-policy petition

Keep a common policy correction in one case when the responsible institution and requested decision are the same. Separate the clean form body from a short evidence PDF. Match every outgoing reference to its claim and verify the current legal version, taxpayer scope, transaction type, tax base and national/local components. Give independent reviewers the final artifact after material reference or scope corrections. Preserve earlier packet and source observations privately.

Before moving to institution selection, compare the entire entered body with the frozen value, including blank lines. Replace an earlier selected attachment when its local bytes changed. Confirm one actual listed file, current bytes and visibility. A mixed-byte character counter can differ from Unicode character count. An upload widget can clear its FileList after accepting a file. Neither difference alone proves truncation or failed upload.

Inspect the effect of a preview action. On the inspected e-People flow, 신청 in the preview closed that overlay; the actual page then exposed its registration button. Persist the uncertain-submission state before the real registration action and use that control once. Do not treat an unchanged label as proof that a control has the same function.

Save the completion receipt and screenshot before downloading anything. Open the saved case from the owner's list, compare the complete body, inspect readable paragraph gaps and verify the actual institution and displayed deadline. Use supported download controls to retrieve the accepted attachment, then compare its bytes with the frozen PDF. Preserve a partial verification honestly if the download remains unavailable. A backend can take longer than the requested wait, so a pending download must not prompt resubmission.

Record the actual notification choices. Keep an internal follow-up date separate from the portal deadline and an automation. Evaluate the eventual reply against each reform request; an explanation of current law alone does not answer whether the requested reform will be accepted.

## Prepare and review supplemental PDFs

Read the accepted body and identify the decision each supplement supports. Keep a case about evaluation ownership focused on a question/reply/remaining-answer table. Use quantitative charts for actual access or monetary comparisons when their evidence supports them. A preview-before-filing instruction authorises preparation and review; it leaves filing for the user's later decision.

Preserve the complete policy-purpose, access, support-allocation and reform argument during evidence review. Scope an unsupported assertion locally rather than replacing the user-requested question with a narrower one. Recipient composition and structural access require different evidence; do not demand unavailable recipient microdata for a rule-based funding comparison. Show relevant support components at the correct policy stage without double counting. See the [argument-scope lesson](lessons-learned.md#lessons-from-preserving-the-policy-argument-and-explaining-entry-payments-on-2026-10-12).

Create new recipient-specific PDFs in private preparation storage. Preserve historical builders, accepted files, original bodies and receipt identifiers. Reuse reviewed calculation inputs while independently checking consequential results. For a dated notice, retain its exact unit, tier, dates, eligibility stages and financing scope. Keep planned lending distinct from approval and amounts outside a designated loan distinct from confirmed own capital. Hold other eligibility and debt conditions constant in synthetic household comparisons. Do not turn priority disadvantage into universal ineligibility.

Keep assumptions that determine the result beside the chart. Use the same take-home estimate for all saving rows. Label maximum saving, illustrative market ratios and comparison rates, future exercise values and proposed fixed amounts. Reconcile additive components and timelines. Describe policy intentions as proposals rather than measured effects. Retain official-source corroboration and archived-source provenance in the private audit without filling recipient pages with internal verification logs.

Run the PDF skill's operation marker once before authoring. Render all authored pages after the final edit and inspect each one. Check the usable frame width, font size, chart labels, source links, page count and grayscale legibility. Repair orphaned references and overlapping content before finalising hashes. Show the real PDFs in the app, record preparation status, and keep attachment delivery unmodified.

If the reader cannot explain an annual-benefit chart, treat that feedback as a presentation defect even when calculations pass. Start with one worked example. Define the comparison rate in concrete annual money terms, explain each benefit component, and use a single total series for amount comparisons. Separate refundable principal, deferred principal and annual advantage. Rebuild only the affected recipient artifact and verify that other reviewed PDFs retain their hashes. See the [annual-support clarity lessons](lessons-learned.md#lessons-from-clarifying-annual-support-on-2026-10-11).

Before freezing a monetary benefit, verify the selected rate from a dated contract or primary actual new-business statistics. Record the product, period, publication date and source table field. Value own funds at an appropriate deposit return after applicable tax. Apply lending rates only to amounts actually borrowed or replaceable by the policy. Keep a statistical reference separate from a personal quote and loan approval. Preserve an arbitrary-rate illustration in history, then replace its current inputs, totals, plot, source conditions and hashes together. See the [observed-rate correction](lessons-learned.md#lessons-from-replacing-the-annual-comparison-rate-on-2026-10-11).

Preserve the financing question when replacing an arbitrary rate. For a requested borrowing comparison, use equal own capital and calculate the interest on additional loan amounts in each alternative. Cancel only identical common financing. Use the loan rate for both the reduced-deposit borrowing and borrowing replaced by deferral. A deposit-yield calculation answers a different question; do not silently substitute it. Label partial-cost tables as additional interest, not total household interest. Keep loan approval and hypothetical amount-band valuation distinct. See the [financing-method correction](lessons-learned.md#lessons-from-restoring-the-borrowing-comparison-on-2026-10-11).

Keep cancellation as an internal arithmetic check. First show the reader the full deposit, amount due at entry and deferred principal. State separately that own capital and an approved bank loan fund the amount due. For the actual KRW 1.17 billion Cheongdam Le El deposit, 30% deferral leaves KRW 819 million due by entry and KRW 351 million deferred; neither figure establishes the household's own capital or bank approval. Remove unexplained common-entry funding labels and reconcile complete funding paths.

Keep the actual notice's unit as the primary example through savings, required financing, complete monthly interest and annual support. Amount bands supplement it. Calculate full bank interest on the savings shortfall and add the entire deferral interest before showing any savings against alternatives. Check product-specific deposit ceilings and distinguish guarantee limits from loan approvals. Recheck the planned entry year against the rate year; label a 2026 calculation as a comparison when 2027 rates are unknown. A 100% saving row must not imply ordinary living expenses or asset eligibility. Review other active artifacts for the same defect, while preserving filed originals and their hashes. See the [actual-unit correction](lessons-learned.md#lessons-from-rebasing-the-housing-comparison-on-2026-10-12).

After filing is authorised, inspect the existing case's current attachment controls. Preserve the receipt and accepted body. Verify the server-saved attachment through its actual download and frozen hash before updating delivery records. ## Compare a complete notice universe

Define the programme, rounds, cutoff date and observation grain before calling an analysis a census. For one housing notice, include every project/area/type row, preserve the original and corrected source versions, and reconcile section and unit totals. Separate new recruitment, reserve recruitment, special accessibility eligibility and actual recipients. Read each amount's source unit and each area group's income/asset rule. Keep raw observations, normalized notice rows and hypothetical funding calculations in separate files.

Use matched household assumptions through savings, necessary financing, full bank and deferral interest, and the conditional annual support valuation. Keep approval, rate year and asset-assessment questions explicit. Include lower-deposit comparison rows; do not use an expensive subset as the complete population. If official summary and raw-table counts disagree, preserve both and investigate the counting definition without deleting rows. Across rounds, track repeated projects and changed prices/rules without treating repeated advertised units as distinct new homes. Review the complete dataset before selecting a few readable examples for a submission. See the [complete-notice lessons](lessons-learned.md#lessons-from-a-complete-notice-census-on-2026-10-12).
