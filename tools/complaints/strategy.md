# 대한민국 행정과 제도 개선을 위한 민원 전략

기준일: 2026년 10월 9일 KST

목표는 대한민국의 행정과 제도에서 불합리한 문제를 찾아 실제 개선까지 확인하는 것이다. 문제 후보를 찾고, 근거를 검증하고, 담당기관에 구체적인 변경을 요구한다. 이후 규정·절차·처분이 바뀌었는지 확인한다. 민원 접수와 답변 수신은 이 과정의 단계다.

공개된 입법·행정·사업 계획도 시행 전에 검토한다. 계획·예고·발의 단계에서 변경 내용과 예상 영향을 확인하고, 의견 기한과 결정 단계에 맞춰 수정안을 준비한다. 이미 발생한 문제의 개선과 시행 전 예방을 같은 `issue_id`로 연결한다. 구체적인 자료 경로와 실행 기준은 [입법·행정의 사전 탐지](early-warning.md)를 따른다.

## 현재 장부와 초기 기록 범위

현재 통합 장부에는 공식 원문으로 대조한 기존 접수 9건과 미접수 준비 사건 2건이 있다. 준비 사건은 접수 건수에 포함하지 않는다. 최신 실행 상태는 비공개 계획과 장부에 기록한다. 정기 조회와 자동 알림은 실행 중이 아니다. [최신 제안 수정 기록](../../data/agents/handoffs/complaints-income-ceiling-2026-10-09.md)을 따른다.

아래 표는 초기 발굴 당시의 기록 범위다. 현재 상태를 나타내는 표가 아니다. 공정위 청구는 이후 통합 장부에 등록했고, ISA 민원도 포털 대조 후 추가했다. 정비사업 관련 과거 기록 3건은 이 장부의 현재 접수 9건과 별도로 대조해야 한다.

| 대상 | 기록 수 | 기록의 기준일 | 관리 상태 | 다음 작업 |
| --- | ---: | --- | --- | --- |
| 청약·특별공급·미리내집 | 7건 | 2026-10-07 | 통합 장부에 등록. 공유 대화의 사용자 인용과 이전 AI 요약이 근거 | 접수번호·제출 본문·답변·연장 통지를 포털 원문과 대조 |
| 공정위 정보공개청구 | 1건 | 기존 정책 메모 2026-09-11 | 별도 로컬 문서에 제출 후 대기로 기록. 통합 장부에는 미등록 | 접수 결과와 현재 상태를 확인한 뒤 통합 |
| 정비사업 관련 접수 | 3건 | 기존 장부 2026-06-24 | 별도 장부에 회신 대기로 기록. 통합 장부에는 미등록 | 원본 기록을 유지하고 최신 상태와 회신을 확인한 뒤 통합 |

초기 표의 합계 11건과 현재 장부의 11개 사건은 구성과 의미가 다르다. 어느 쪽도 계정의 모든 제출 내역을 확인한 결과는 아니다. 오래된 대기 기록만으로 현재 미회신이나 처리기한 위반을 판단하지 않는다. 전기통신사업법 시행령 의견 제출과 ETF 세제 관련 후보의 제출 사실은 별도로 확인한다.

실제 접수번호, 제출 본문, 회신과 증거 파일은 Git에서 제외되는 `data/complaints/`에 둔다. 등록 형식과 명령은 [민원 추적과 제출 자동화](README.md)를 따른다.

## 문제 후보를 찾는 기준

‘비상식적이다’라는 판단을 검증할 수 있는 질문으로 바꾼다. 문제 후보마다 적용 대상, 기준일, 실제 사례와 예상되는 영향을 적는다. 아래 기준은 검토를 시작하는 기준이며 제도의 부당함을 확정하는 기준은 아니다.

구체적인 발굴 방법은 [불합리한 행정과 제도를 찾는 조사 방법](discovery-research.md)에 정리했다. 반복 민원 분석, 규칙과 근거의 비교, 실제 절차의 부담 측정을 함께 사용한다. 공식 자료에서 확인한 방법, 국내 자료 경로, 사례 검토와 후보 기록 양식을 포함한다.

| 문제 후보 | 검증할 질문 | 먼저 확보할 근거 |
| --- | --- | --- |
| 같은 상황의 다른 처리 | 비교 대상 사이에 다른 처리를 정당화할 차이가 있는가 | 적용 규정, 비교 가능한 사례, 기관의 설명 |
| 기준 부근의 급격한 불이익 | 소득·자산·규모가 조금 달라졌을 때 부담이나 지원이 얼마나 달라지는가 | 기준표, 경계 전후 계산, 제도 목적 |
| 목적에 비해 큰 비용 | 이용자의 시간·비용·위험에 비해 절차의 효과가 있는가 | 처리 단계, 실제 소요시간·비용, 효과 검토 자료 |
| 기관이나 규정 사이의 모순 | 같은 사실에 대한 안내나 적용 조건이 서로 충돌하는가 | 기관별 답변 원문, 조문, 안내의 적용 시점 |
| 반복되는 처리 오류 | 개별 실수인가, 같은 원인으로 되풀이되는 문제인가 | 독립된 사례, 정정 기록, 업무 기준 |

입법예고, 규제영향분석, 감사 결과, 공식 통계, 기존 민원 답변과 직접 겪은 사례에서 후보를 모은다. 보도나 온라인 경험담은 원문을 찾는 단서로 사용한다. 제도의 목적과 반대 근거도 함께 검토한다. 제도에 대한 불만과 확인된 오류를 구분한다.

## 우선순위와 진행 건수

동시에 집중할 문제는 3개 이내로 둔다. 나머지 후보는 검토 대기 목록으로 관리한다. 다음 네 기준으로 우선순위를 비교한다. 수치 근거가 없으면 영향받는 사람 수나 비용을 임의로 계산하지 않고 미확인으로 남긴다.

| 기준 | 우선 검토할 문제 |
| --- | --- |
| 영향 | 권리 침해나 시간·비용 부담이 크거나 적용 대상이 넓은 문제 |
| 반복성 | 여러 사례에서 같은 원인이 나타나는 문제 |
| 근거 | 규정 원문, 실제 사례, 공식 답변으로 쟁점을 검증할 수 있는 문제 |
| 변경 가능성 | 담당기관과 수정할 규정·절차를 특정할 수 있는 문제 |

사전 탐지에서는 예상 영향과 되돌리기 어려움을 검토한다. 심각성과 마감 임박 여부를 따로 기록한다. 추진 사실이 확인돼도 예상 피해가 확인됐다고 표시하지 않는다. 법률안·하위규정·사업의 각각의 원문과 수정·대안 관계를 연결한다.

개별 처분의 정정, 행정 절차의 수정, 지침의 변경, 법령의 개정은 필요한 근거와 담당자가 다르다. 문제를 선정할 때 어느 수준의 변경이 필요한지 먼저 구분한다. 접수나 의견 제출 기한이 있는 사안은 기한을 확인해 별도로 우선 처리한다.

## 문제별 근거 문서

해결하려는 문제 하나에 `issue_id`를 부여한다. 실제 제출 절차마다 `case_id`를 부여한다. 후속 절차는 `parent_case_id`로 앞선 사건과 연결한다. 문제별 근거 문서는 다음 내용을 포함한다.

1. 현재 규칙과 적용 범위: 조문·지침·안내, 시행일, 담당기관.
2. 실제 사례와 영향: 발생일, 처리 내용, 시간·비용·권리상의 부담.
3. 기관의 설명과 반대 근거: 제도 목적, 다른 처리의 이유, 아직 검증되지 않은 가정.
4. 질문별 근거: 요청한 자료, 답변 원문, 답변된 부분과 남은 부분.
5. 변경안: 바꿀 조문·절차·안내와 구체적인 대안.
6. 완료 조건: 오류 정정이나 실제 변경을 어떤 자료로 확인할지.
7. 다음 행동: 필요한 자료, 담당기관, 다음 확인일.

예를 들어 청약 문제는 ‘소득기준이 이상하다’에서 ‘해당 소득기준과 실제 자금조달 가능성을 함께 검토한 자료가 있는가’로 질문을 좁힌다. 기관의 검토 자료와 실제 적용 결과를 확보한 뒤 기준 조정이나 설명 보완의 필요성을 판단한다. 자료 부존재 통지는 해당 기관·기간·청구 범위에 한정해 해석한다.

## 처리 순서와 제출 경로

1. 문제와 원하는 결과를 한 문장씩 적는다.
2. 적용 규정과 실제 사례를 확인한다.
3. 설명이 필요한 부분과 기존 자료가 필요한 부분을 구분한다.
4. 담당기관과 제출 경로를 정한다.
5. 질문마다 답변 또는 조치의 완료 조건을 붙여 제출 내용을 준비한다.
6. 회신을 질문별로 비교하고 남은 항목에 맞는 후속 절차를 정한다.
7. 실제 변경을 확인하거나, 보류·종료 이유와 다시 검토할 조건을 기록한다.

| 목적 | 검토할 경로 | 작성할 내용 |
| --- | --- | --- |
| 사실·처리 오류의 정정 또는 정책 설명 | 담당기관 일반민원 | 오류의 위치, 사례, 정정하거나 설명할 항목 |
| 기관이 보유한 검토 근거 확보 | 정보공개청구 | 식별할 수 있는 기존 자료의 종류·기간·주제 |
| 법령이나 제도의 변경 | 입법제안 또는 입법예고 의견 제출 | 변경할 규정, 변경 이유, 대안과 예상 영향 |
| 부당한 행정으로 발생한 권리 침해·불편·부담의 해결 | 권익위 고충민원 | 구체적인 행정행위, 피해, 이전 민원과 답변, 요구 조치 |
| 담당 공무원의 의무 미이행에 대한 검토 | 소극행정 신고 | 해야 할 업무, 하지 않은 행위, 경과와 피해의 근거 |

정보공개청구는 기관이 보유·관리하는 기존 자료를 확보하는 절차로 사용한다. 기관이 정보를 보유하지 않거나 청구가 질의 성격인 경우에는 민원으로 처리될 수 있다. [정보공개법 제11조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1011235965)

국민참여입법센터는 입법예고 의견 제출과 불편법령신고 등 입법제안 경로를 제공한다. 해당 규정의 개정 단계와 의견 제출 기간을 확인한다. [국민참여입법센터](https://opinion.lawmaking.go.kr/)

고충민원은 부당하거나 소극적인 행정과 불합리한 행정제도로 발생한 권리 침해·불편·부담을 다룬다. 일반적인 제도 문의와 구체적인 피해 구제 요청을 구분한다. [권익위 고충민원 안내](https://www.acrc.go.kr/menu.es?linkOpt=ext&mid=a10201010100)

소극행정 신고는 업무의 미이행이나 책임 회피 등의 근거를 확인한 뒤 검토한다. 답변에 대한 단순한 불만이나 적법한 처리기간 중 조치 요구만으로 소극행정을 판단하지 않는다. [교육부 소극행정 신고 안내](https://www.moe.go.kr/sub/infoRenew.do?m=011704&page=011704&s=moe)

## 자동화 범위와 결과 확인

자동화는 기존 기록의 조회와 근거 보관부터 연결한다. 상태 조회에서 확인한 사실과 답변에 대한 판단은 따로 기록한다.

| 순서 | 자동화할 작업 | 완료를 확인할 근거 |
| --- | --- | --- |
| 1 | 접수번호·담당기관·상태·예정일 조회 | 해당 사건의 포털 원문과 관찰 시점 |
| 2 | 이송·연장·신규 답변 기록 | 원래 값과 변경 값, 통지 원문 |
| 3 | 제출 본문·접수증·답변 원본 보관 | 저장 파일, 출처, 파일 해시 |
| 4 | 질문별 답변 대조 | 답변 문장 또는 원문 위치 |
| 5 | 다음 행동과 후속 초안 작성 | 미해결 질문, 선택한 절차와 구체적인 요청 |
| 6 | 확정된 제출 내용의 화면 입력과 접수 확인 | 입력값 대조, 접수 성공 화면과 접수번호 |

새로운 외부 제출은 실제 기관·본문·첨부가 특정된 실행 지시에 따라 진행한다. 같은 질문에 대한 후속 제출은 앞선 답변에서 무엇이 남았는지 기록한다. 접수 결과가 불확실하면 계정의 신청내역을 확인하기 전 재제출하지 않는다. 세부 실행은 [computer use 실행 지침](computer-use.md)을 따른다.

정기 조회를 연결할 때는 신규 답변, 이송, 연장, 의미 있는 기한 변경, 필요한 사용자 조치가 있을 때 알린다. 현재 운영 코드에는 반복 실행 일정이나 알림 연결이 없다. 송파구 새올전자민원창구는 현재 장부의 지원 포털에 포함되지 않아, 해당 사건을 통합하기 전에 포털 식별자와 실행 경로를 추가해야 한다.

처리 상태와 해결 상태는 분리한다. 답변 수신이나 포털의 처리 완료 표시는 문제 해결을 뜻하지 않는다. ‘검토하겠습니다’라는 답변만으로 `resolution_status=resolved`를 기록하지 않는다.

| 결과 | 기록 방법 |
| --- | --- |
| 오류 정정 | 정정 전후 기록과 적용 결과를 확인 |
| 절차·안내·규정 변경 | 변경 원문, 시행일과 실제 적용 범위를 확인 |
| 시간·비용 감소 | 비교 조건이 같은 전후 자료로 확인 |
